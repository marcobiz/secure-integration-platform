# `v0.1.0-alpha.1` — PUBLIC TECHNICAL PREVIEW

Secure Integration Platform `v0.1.0-alpha.1` was published on 24 August 2026 as a
[GitHub public prerelease](https://github.com/marcobiz/secure-integration-platform/releases/tag/v0.1.0-alpha.1)
from source commit
[`ee3072be5e34a7b0477907a2580dcf454b8a4aba`](https://github.com/marcobiz/secure-integration-platform/commit/ee3072be5e34a7b0477907a2580dcf454b8a4aba).
It is an alpha technical preview: it is **not production-ready**, carries no SLA, and
makes no certification, accreditation, enterprise-support, high-availability,
disaster-recovery, API-stability, artifact-signing, provenance, or absolute
binary-reproducibility claim. The NuGet package was not published to NuGet.org and the
container images were not published to a registry.

## Supported evaluation path

Follow the

## Verification and manifest errata

`SHA256SUMS` binds exactly the five product artifacts and uses candidate-relative paths
under `artifacts/`. Place those five files in an `artifacts` directory before running a
standard checksum verifier, or compare each listed hash directly. Verify the two public
SBOMs, `release-manifest.json`, and `SHA256SUMS` against the GitHub SHA-256 values in the
[publication attestation](https://github.com/marcobiz/secure-integration-platform/blob/main/docs/releases/0.1.0-alpha.1-publication-attestation.json)
and the GitHub Release API.

The five product artifact hashes agree across the published manifest, `SHA256SUMS`, and
GitHub, and all nine downloaded assets match their GitHub digests. The manifest's
`claims.publicReleaseGo=false` records its pre-publication candidate state. The later
publication makes that field a historical state erratum, not evidence of corruption; the
published manifest is not being replaced.

No artifact signing or provenance is claimed. Archive bytes may vary between independent
builds; the reviewed cross-run identity is the normalized Core inventory digest, not
absolute byte-for-byte reproducibility.
